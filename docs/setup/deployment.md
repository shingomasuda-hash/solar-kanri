# デプロイ / Deployment

Vercel などのサーバーレス環境に載せる場合の手順。ローカル開発は
[`database.md`](database.md) を参照。

---

## ログイン画面でエラーになるとき

「ログイン処理でエラーが発生しました」は、パスワード間違いではありません。
**サーバー側でデータベースに到達できていない**ときのメッセージです。
現在は原因を切り分けて表示するので、画面の文言をそのまま読んでください。

| 画面の文言                        | 原因                                       | 対処                                             |
| --------------------------------- | ------------------------------------------ | ------------------------------------------------ |
| DATABASE_URL が設定されていません | 環境変数の未設定                           | Vercel → Settings → Environment Variables に追加 |
| データベースに接続できません      | 接続先違い／IP許可なし／DBが起動していない | 接続先ホストと、DB側の接続許可設定を確認         |
| 認証に失敗しました                | ユーザー名・パスワード違い                 | DATABASE_URL の認証情報を確認                    |
| データベースが存在しません        | DB名違い                                   | DATABASE_URL の末尾のDB名を確認                  |
| テーブルがありません              | マイグレーション未実行                     | 下記「3. マイグレーションとシード」              |

いずれも時間をおいても直りません。設定を変えるまで同じ結果になります。

## 1. データベースを用意する

**ローカルの PostgreSQL は使えません。** Vercel の関数から到達できないためです。
外部から接続できる PostgreSQL 16 以上を用意してください（Neon、Supabase、
Amazon RDS など）。

### Neon の場合

1. [neon.com](https://neon.com) でアカウントを作成
2. **Create project** — Region は **Asia Pacific (Singapore)**。
   Neon に東京リージョンはなく、Asia Pacific は Singapore と Sydney だけです
   （[Regions](https://neon.com/docs/introduction/regions)）。
   PostgreSQL のバージョンは既定のままで構いません
3. 作成直後に表示される **Connection string** をコピー

Neon は接続文字列を2種類出します。**両方を使い分けます。**

|            | ホスト名                            | 用途                                  |
| ---------- | ----------------------------------- | ------------------------------------- |
| **Pooled** | `...-pooler.<region>.aws.neon.tech` | Vercel の環境変数に設定するのはこちら |
| **Direct** | `-pooler` が入らない                | マイグレーションを流すのはこちら      |

画面の **Connection Details** に「Pooled connection」のトグルがあり、
オンにすると `-pooler` 付きになります。

理由は用途が逆だからです。サーバーレスは関数インスタンスごとに接続を張るので、
アプリ側はプーラーを通さないと接続数の上限に当たります。一方 DDL
（テーブル作成）はプーラーと相性が悪く、途中で失敗することがあるため、
マイグレーションは直接接続で流します。

どちらの文字列にも `?sslmode=require` が含まれていることを確認してください。

### 関数とデータベースを同じ地域に置く

Vercel の関数リージョンは既定で `iad1`（米国東部）です。データベースだけ
Singapore にすると、1リクエストごとに太平洋を2往復します。このアプリは1画面で
複数回問い合わせるので、往復回数がそのまま体感差になります。

**Vercel → Settings → Functions → Function Region → Singapore (sin1)**

これで関数とデータベースが並び、日本からの往復は1回だけになります。

国内リージョンが業務要件になる場合、Neon では現状対応できません。Supabase の
Tokyo か Cloud SQL が選択肢ですが、いずれも無料枠の話ではなくなります。

### 接続プーリング

サーバーレスは関数インスタンスごとに接続を張るため、素の接続数ではすぐ上限に達します。
プーラー経由の接続文字列を使ってください。

- **Neon** — ホスト名に `-pooler` が入った接続文字列
- **Supabase** — Connection pooling のポート `6543`
- **PgBouncer 一般** — `?pgbouncer=true` を付与

マイグレーションは**プーラーを経由しない直接接続**で実行してください。
DDL はプーラーと相性が悪く、途中で失敗することがあります。

## 2. 環境変数

Vercel → Settings → Environment Variables。

| 変数                              | 必須         | 内容                                         |
| --------------------------------- | ------------ | -------------------------------------------- |
| `DATABASE_URL`                    | **必須**     | PostgreSQL 接続文字列（プーラー経由）        |
| `SEED_ADMIN_PASSWORD`             | シード時のみ | 初期アカウントのパスワード。**必ず変更する** |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | 任意         | 未設定でも動作（地図が手動入力になる）       |
| `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`  | 任意         | ベクター地図スタイル                         |
| `GOOGLE_GEOCODING_API_KEY`        | 任意         | 住所検索。サーバー側専用、IP制限を推奨       |
| `ANTHROPIC_API_KEY`               | 任意         | 未設定なら Copilot のみ無効、他は動作        |
| `SOLAR_PROVIDER_ORDER`            | 任意         | 既定 `manual,pvgis`                          |

`NEXT_PUBLIC_` が付くものだけがブラウザに露出します。それ以外は絶対に付けないでください。

`.env.example` には `SESSION_SECRET` の記載がありますが、**現在のコードは使用していません**。
セッションはランダムなトークンをDBに保存する方式で、署名鍵を必要としません
（`src/server/auth/session.ts`）。設定しても害はありませんが、必須ではありません。

## 3. マイグレーションとシード

ビルドは `prisma generate && next build` なので、Prisma クライアントは自動生成されます。
**マイグレーションは自動では走りません。** 手元から本番DBに対して実行してください。

```bash
# プーラーを経由しない直接接続で
DATABASE_URL="postgresql://...直接接続..." npx prisma migrate deploy
DATABASE_URL="postgresql://...直接接続..." SEED_ADMIN_PASSWORD='<強いパスワード>' npm run db:seed
```

デモデータも入れる場合:

```bash
DATABASE_URL="postgresql://...直接接続..." npm run db:seed:demo
```

シード後のログインIDは `admin@example.com` / `manager@example.com` /
`sales@example.com` / `viewer@example.com`、パスワードは `SEED_ADMIN_PASSWORD` の値です。

**初回ログイン後にパスワードを変更してください。** シードのアカウントは
メールアドレスが公開情報と同じ形式なので、そのままにしないでください。

## 4. 既知の制約

### ログイン試行回数の制限が関数ごとになる

レート制限はプロセスメモリ上のカウンタです（OI-106）。サーバーレスでは関数インスタンス
ごとに別々のカウンタになるため、実効的な上限がインスタンス数だけ緩みます。
外部公開する場合は共有ストア（Redis など）への差し替えを検討してください。
差し替え点は `src/server/auth/rate-limit.ts` の3関数だけです。

### 監査ログとセッションはDBに載る

ファイルシステムには何も書きません。サーバーレスの一時ファイルシステムに依存する
処理はないので、その点の追加設定は不要です。

## 5. 確認

デプロイ後、管理者でログインして **管理 → システム状態** を開いてください。
7項目すべての状態が表示されます。データベース以外が赤でも業務フローは動きますが、
リリースを告知する前には緑になっていることを確認してください。
